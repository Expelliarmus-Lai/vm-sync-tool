# VM Sync Tool 使用说明

语言：[中文](USER_GUIDE.md) | [English](USER_GUIDE.en.md)

VM Sync Tool 是一个 Windows 桌面工具，用于在宿主机和 VMware Workstation 虚拟机之间同步 Keil 固件工程。它通过 VMware 的 `vmrun.exe` 和 VMware Tools 操作虚拟机文件，不依赖网络共享或虚拟机网卡。

## 使用前提

使用前请确认电脑和虚拟机已经准备好：

- Windows。
- VMware Workstation。
- 目标虚拟机已经安装 VMware Tools。
- 虚拟机能正常启动并进入 Windows 桌面。
- 虚拟机里已经安装并可使用 Keil MDK。
- 虚拟机 Windows 账户有密码，并且可被 `vmrun -gu/-gp` 登录。

本工具不会安装 VMware、VMware Tools、Keil，也不会创建虚拟机。

## 发布包内容

发布包目录应包含：

```text
VM Sync/
  VM Sync.exe
  _internal/
  README.md
  README.en.md
  LICENSE
  config.example.json
```

双击 `VM Sync.exe` 即可启动。普通使用者不需要安装 Python，也不需要运行 bat/cmd/vbs。

第一次运行时，程序会在 `VM Sync.exe` 同目录生成 `config.json`。这个文件保存本机路径、虚拟机路径、VM 用户名和密码，请勿公开分享。

`config.example.json` 是公开模板，用来展示配置文件格式；程序真正读取和保存的是 `config.json`。

界面右上角有一个小型 `中 / EN` 语言切换按钮。首次启动会优先读取 Windows 显示/UI 语言；手动切换后，选择会保存到 `config.json`，下次启动继续使用该语言。

## 单项目和双项目模式

默认只显示项目 1，窗口宽度和旧版单项目界面保持一致，默认窗口大小为 `700x955`，通常可以完整显示单项目界面。需要同时监听第二套代码时，点击“添加同步项目”，界面会向右展开项目 2 的配置栏和日志栏，并切换到 `1180x955` 的双项目布局；点击“停用项目 2”会暂停项目 2 并收回到单项目布局。

项目 1 和项目 2 共用同一个 VMX、VM 用户名和 VM 密码，但每个项目都有独立的宿主机工程路径、VM 工程路径、`.bin` 相对路径、固件回传目录、启动/暂停按钮、保存检测、全量同步/取消和日志栏。旧版单项目配置会自动填入项目 1，项目 2 默认关闭。

顶部“启动/暂停”会作用于所有已启用项目。点击顶部“启动”时，如果任一已启用项目预检失败，所有项目都会保持停止；已经预检通过的项目日志会提示它没有启动，是因为另一个项目配置需要先修正。单独点击某个项目里的“启动”或“暂停”只影响该项目。

## 配置项说明

打开软件后，先填写顶部共享 VM 配置，再填写每个项目自己的配置，然后点击项目栏里的“保存并检测”。

共享 VM 配置：

| 配置项 | 含义 | 示例 |
|---|---|---|
| VMX 路径 | 虚拟机 `.vmx` 文件路径。必须是当前正在运行的虚拟机。 | `D:\VMs\Win10\Windows 10.vmx` |
| VM 用户名 | 虚拟机 Windows 登录用户名，用于 `vmrun` 操作文件。 | `h` |
| VM 密码 | 虚拟机 Windows 登录密码。建议不要使用空密码。 | `123456` |

每个项目独立配置：

| 配置项 | 含义 | 示例 |
|---|---|---|
| 宿主机工程路径 | 宿主机上编辑的 Keil 工程根目录。 | `C:\Users\Administrator\Desktop\project` |
| VM 工程路径 | 虚拟机里的工程根目录。全量同步会解压到这里，增量同步也会写到这里。 | `C:\Users\h\Desktop\project` |
| `.bin` 相对路径 | 相对于 VM 工程路径的 `.bin` 文件或目录。 | `Output\RL6492\firmware.bin` |
| 固件回传目录 | `.bin` 回传到宿主机的目录。 | `C:\Users\Administrator\Desktop\bin` |

两个启用项目的宿主机工程路径和 VM 工程路径不能互相包含。例如，不要把项目 2 放在项目 1 目录的子目录中，也不要让两个项目写到同一个 VM 工程目录下；预检会阻止这类配置，以避免文件传输混淆。

### `.bin` 相对路径怎么填

推荐填写具体 `.bin` 文件：

```text
Output\RL6492\firmware.bin
```

也可以先填写 `.bin` 所在目录：

```text
Output\RL6492
```

如果该目录下只有一个 `.bin`，软件会自动识别、在日志中提示选择了哪个文件，并把配置栏补全成具体 `.bin` 相对路径后保存到 `config.json`。如果有多个 `.bin`，软件会报错并提示你选择具体文件名。

如果你粘贴的是 VM 工程路径下面的完整绝对路径，软件会自动换算成相对路径并用 Windows 反斜杠显示，例如 `C:\Users\h\Desktop\project\Output\RL6492` 会保存为 `Output\RL6492`。如果绝对路径不在“VM 工程路径”下面，检测会失败，需要改成正确的相对路径或正确的 VM 工程路径。

## 基本操作流程

1. 启动 VMware Workstation，并打开目标虚拟机桌面。
2. 双击 `VM Sync.exe`。
3. 填写配置项。
4. 点击“保存并检测”。
5. 首次配置工程时，点击“全量同步”，把整个工程复制到虚拟机。
6. 如果需要第二套工程，点击“添加同步项目”，填写项目 2 的路径并执行“保存并检测”。
7. 点击顶部“启动”启动所有已启用项目，或点击某个项目栏里的“启动”只启动该项目。软件会先保存配置并执行与“保存并检测”相同的检查；检查通过后，开始监听宿主机文件变化和虚拟机 `.bin` 输出。
8. 确认对应项目日志里已经记录当前 `.bin` 状态后，再在虚拟机里用 Keil 编译工程。
9. `.bin` 内容发生变化后，软件会自动回传到该项目的“固件回传目录”。

## 全量同步和启动同步的区别

### 全量同步

全量同步会把宿主机工程目录下的所有文件打包上传到虚拟机，并解压到 VM 工程路径。它适合第一次配置、工程结构变动较大、或者虚拟机里的工程缺文件时使用。

每个项目的全量同步互相独立。项目 1 的“全量同步”只使用项目 1 的宿主机工程路径和 VM 工程路径，项目 2 同理。全量同步进行时，对应项目的配置栏和顶部启动按钮会置灰，“全量同步”按钮会变成“取消全量同步”。点击取消后，软件不会强行杀掉正在进行的 VM 文件操作，而是等待当前步骤结束后停止后续步骤，并清理本机临时压缩包、VM 临时压缩包和 VM 临时解压目录。如果清理失败，日志会给出需要手动删除的临时路径。

覆盖规则：VM 里同相对路径的文件会被宿主机文件覆盖；VM 里多出来的文件不会被删除。全量同步会先解压到 VM 临时目录，再从临时目录覆盖到 VM 工程路径。也就是说，全量同步以宿主机现有文件为准更新同名文件，但不会清空 VM 目录。

### 启动同步

启动同步后，软件会做两件事：

- 监听宿主机工程文件变化，增量同步到虚拟机。
- 轮询虚拟机 `.bin` 输出文件，检测到内容变化后回传到宿主机。

点击某个项目的“启动”时，软件会先保存当前配置，在该项目日志中提示路径已保存至 `config.json` 文件，并执行与“保存并检测”相同的检查。如果检查失败，同步不会启动，请先按日志提示修正配置。点击顶部“启动”时会先检查所有已启用项目，只要其中一个失败，全部保持停止，避免只有一部分项目在错误配置下运行。

正确时机是：把工程文件同步到虚拟机后，先点击“启动”，再去 Keil 里编译。不要先编译好再启动软件等待回传；启动前已经存在的 `.bin` 会被记录为基线，不会立刻覆盖宿主机输出目录。启动后如果你再次编译，即使新 `.bin` 内容相同但时间更新，软件也会回传一次，避免刚启动后重复编译却没有回传的困惑。

增量同步只处理本项目宿主机路径里新增或修改的文件，并且只同步配置中 `watch_extensions` 包含的扩展名。软件会比较磁盘文件内容 hash，只有内容真的变化时才上传；编辑器探测、单纯时间戳变化、以及 VS Code 中尚未保存的修改不会上传到 VM。同步时会先把文件复制到本项目 VM 目标目录下的临时文件，再移动覆盖最终路径，以降低暂停或退出时直接写坏目标文件的风险。同相对路径的 VM 文件会被覆盖；删除、重命名和不在扩展名列表里的文件不会自动同步。两个项目的上传队列和 hash 基线互相独立，单个项目上传超时只会暂停该项目的增量上传，不影响另一个项目。

`.bin` 回传只针对本项目配置的 `.bin` 文件。启动同步时，软件会把 VM 当前已有的 `.bin` 作为基线，不会立即拉回来覆盖宿主机旧文件；启动后 `.bin` 内容变化时，才会回传并覆盖本项目固件回传目录里的同名文件。首次基线记录后，如果 `.bin` 时间更新但内容不变，软件会额外回传一次；之后如果只是时间变化但内容没变，不会继续覆盖，并会像“固件就绪”一样通过托盘通知提示。停止某个项目后，迟到的 `.bin` 轮询结果不会再触发该项目日志、通知或覆盖，也不会影响另一个项目。

## 系统托盘

关闭主窗口只会隐藏到系统托盘，同步服务会继续运行。单击或双击托盘图标只会显示主窗口，不会启动或暂停同步。

右键托盘图标可以打开菜单。菜单会显示当前状态，并提供“启动同步/暂停同步”“显示窗口”和“退出”。其中“启动同步/暂停同步”是主要操作，在菜单中会加粗显示；“显示窗口”不会加粗。需要完全退出软件时，请通过托盘右键菜单选择“退出”。

## 常见问题

### 打开后提示找不到 vmrun.exe

请确认已经安装 VMware Workstation。软件会自动探测常见安装路径和 PATH 中的 `vmrun.exe`。

### 提示配置的 VMX 当前未运行

请先在 VMware Workstation 中启动对应虚拟机，并确认配置的 VMX 路径就是这个正在运行的虚拟机。

### 提示 VM 目录下有多个 `.bin`

把 `.bin` 相对路径从目录改成具体文件名，例如：

```text
Output\RL6492\firmware.bin
```

### 启动后没有立刻回传 `.bin`

这是正常行为。请先启动同步，再去 Keil 编译；启动前已经存在的 `.bin` 会作为基线，不会立刻回传。见上面的 `.bin` 回传规则。

### 关闭窗口后软件还在运行

关闭窗口只会隐藏到系统托盘，同步仍然运行。单击或双击托盘图标可重新显示窗口；需要完全退出时，请右键托盘图标，选择“退出”。
